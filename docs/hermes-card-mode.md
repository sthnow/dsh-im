# Legacy Hermes-inspired 飞书卡片

> 本文只描述旧的 `hermes_card` 展示模式。固定 HFC v5.0.25 Python 后端、逐机器人白名单、receipt-gated 独立交互 rail、状态协议及维护升级流程，请看 [HFC 定制分支维护指南](hfc-maintenance.md)。两条展示路径不能混为一谈。

## 定位和选择方式

旧模式最初基于 dsh-im v5.10.0（`c826bfa415d79669d8ebba206cf4a1eac554d8e2`）开发，是 **legacy Hermes-inspired 的独立 JavaScript 实现**，不是直接加载 Hermes/HFC renderer，也不是固定 vendor Python 后端的开关。

在 IM机器人 → 飞书 → 对应机器人 → 任务过程展示，选择“Hermes 风格卡片（状态、正文、过程与统计）”，模式标识为 `hermes_card`。原有选项、默认值和已有机器人配置不自动迁移；切回原选项恢复原展示。新版 HFC 的选择条件另由 `hfcPresentation` 的 per-bot backend 和 session 白名单控制，见新指南；不要只凭 UI 文案推断正在使用哪条链路。

## 旧模式的展示和交付边界

以下保留旧模式的设计说明，不作为新 HFC 后端能力说明：

- 独立渲染状态、正文、可折叠执行过程和统计页脚。完成态省略顶部标题，在分隔线后的页脚显示完成状态；其他状态保留标题。工具摘要在正文后最多三条，并受字节预算限制，复用过程面板中的真实状态，不是 HFC 全部工具详情的完整复刻。
- 共用的“展开思考过程／展开工具摘要”任一开关开启，旧 Hermes 过程面板即展开，完成后保持设置；原实时过程卡仍分别控制两个面板并在完成后折叠。
- 正文消费当前 step 的文字增量；中间回复作为进度说明。明确 canonical reasoning 单独标识为推理，不把进度说明冒充推理；旧模式不逐 token 推送 reasoning。
- 过程条目按本插件观察到更新的顺序倒序排列。缺少可信统一源时间戳，乱序送达时不保证源事件顺序；历史有界，过长过程条目可能在展示层截短。工具调用先显示进行中，只有匹配真实 callId 的结果才能标记成功或失败，无结果时结束为中断。
- 终态“本轮回复已结束”只描述这一轮，不代表 Goal、子代理或后台 job 已全部完成；未接入独立后台生命周期，不能凭工具返回推断后台业务成功。
- 页脚耗时是整轮展示链路墙钟时间，含工具与用户等待，不是模型解码耗时。Token 来自该轮可归属的 durable model assistant/message usage，不是会话累计；缺字段隐藏对应总量，混合模型隐藏单一模型标签。旧模式没有可靠数据源时不估算生成速率、上下文占用或订阅额度。新 HFC 的指标接入另见新指南，不以此旧说明否定或证明新后端能力。
- 卡片超容量沿既有 Markdown 分段机制分多卡，代码围栏/表头可能补齐、段间空白可能规范化，不应静默截断答案；有界过程历史不是完整执行记录，完整记录仍在 DSH。
- 旧模式审批/提问复用原交互卡和权限流程，历史正文冻结，续答卡创建在交互之后；不扩大批准范围、不增加永久批准，不移植 Hermes sidecar/hooks。
- 旧链更新失败时会尝试最终答案文本降级；Goal 轮次也检查封存结果并尝试既有 Markdown 分片。发送前检查取消和重绑定，但在途请求无法撤销；部分分片成功或投递 unknown 时可能重复，也不保证最终送达。**这不是新 HFC 后端“unknown 不自动 retry”的 receipt-gated 单 owner 契约**，不得把旧链降级策略搬到新链。附件仍走原有回传。

## 旧实时流与镜像限制

- 归属确认前最多暂存 256 个事件、65536 字符；溢出可能暂缺前缀，开放流可历史重放补齐，否则等待 durable 定稿。
- 活动 attempt 的 Host/跟踪器保留流帧并轮询重读，极长流的内存与处理压力没有完整基准。若适配器实例替换而旧跟踪器仍活跃，实例内 attempt 序号可能重置，旧阶段曾记录可能拒绝新片段的生命周期风险；不应称作普通重启必现，也不能不复核当前源码就宣称仍存在或已修复。错过 stream start 时需等待定稿。
- 失败终态在可识别 attempt 的 stream-end 丢失时撤回未定稿草稿；取消/中断可能保留部分草稿并标记停止，缺少 attempt 标识的旧协议不能安全猜测撤回。
- 独立 Goal 自动轮次依赖可归属的 durable 事件，不等同普通 IM 回复逐 token 流。只有连续原始事件足以证明轮次边界时补充归属，向前最多 4096 事件；序号缺口、Session 不可用、超范围或历史冷启动时不猜测。
- 无法确认轮次时，仅尝试向仍绑定目标发无正文提示；无法核对话题锚点时不发送。提示可能依赖事件重放，进程内去重有界，重启/淘汰/unknown 后可能重复；不保证提示或最终答案送达。
- 会话同步到私聊的镜像及重启恢复保留原卡片/持久化路径，不直接切换此 renderer。目标核验与网络发送非原子，核验后解绑无法撤回请求，长答案分片间可能重绑。旧说明中的持久化失败/崩溃恢复风险不能作为整个新状态层已无保护的结论；维护分支已加入独立状态协调/删除屏障，其能力和限制见新指南。
- 遗留卡片的显示终态不能证明异常退出前的真实执行结果。“本轮回复已结束”不修复后台生命周期证据缺口，未接入前不展示猜测的“后台运行中/全部完成”。

## 安装、切换和回退

安装、Host 重载、灰度配置和状态回退必须另获授权，并按插件管理器实际 `nextStep` 操作；不要直接修改已安装依赖。安装包不应自动切换既有机器人展示模式。回退到上游精确版本前，先停全部写者并制定 JSON 与协调数据库的一致性计划；旧版不认识新状态协议，不能并发写，也不可删除或单独回滚 `.coord.sqlite` 来绕过墓碑。仅切回 UI 展示模式不等于回退代码或状态。完整流程见 [维护和回退指南](hfc-maintenance.md)。
